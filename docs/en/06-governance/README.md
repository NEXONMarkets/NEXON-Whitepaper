# Governance

Governance must not be inferred from token ownership. The approved economic paper defines XO as the Staking Principal Token and EXON as the Core Value Token and spot asset. It does not publish an on-chain voting mechanism or grant either asset a current vote.

The NEXON narrative positions XO as the Value Anchor associated with staking, participation, rights and long-term value accumulation. Any governance utility within that position is **Roadmap**. Until a formal framework is published, governance remains administration by accountable project operators under disclosed controls.

## Current parameter administration

The project team currently administers configurable parameters, which may include staking settings, reward payout ranges, round-specific terms and operating controls. Every production change should carry:

1. an effective time and unique parameter version;
2. the exact fields changed and rationale;
3. the scope of new and existing orders affected;
4. advance public notice where practical through an official channel;
5. an auditable record that prevents silent retroactive changes to closed epochs;
6. an emergency process, responsible approvers and a post-incident report where normal notice is impossible.

Interfaces should show the version governing a user's order. A general statement that parameters are adjustable is not sufficient if the user cannot identify which values applied at execution.

## Roadmap design questions

XO governance remains Roadmap. Before any such function can become live, the project must define what is governed and what is not. At minimum, a published design should cover proposal eligibility, voting or signaling method, quorum, thresholds, delegation, timelocks, execution authority, conflicts of interest, concentrated holdings, emergency powers and appeal or correction.

Some decisions may remain with regulated providers or contractual operators regardless of community preference. A token vote cannot direct a card issuer to breach legal obligations, change a merchant's fulfillment duty, override custody terms or waive jurisdictional eligibility. Economic parameter changes may also require risk, legal and technical review beyond a simple popularity signal.

## Disclosure and open fields

The team may not present unpublished fields as decided. Numerical EXON total supply, complete allocation, initial float, future-round limits and the complete Differential Matching Bonus table remain Open. Roadmap XO governance thresholds, voting scope and any reward for participation are also Open.

A future written decision should update the authority registry, both language trees, user interfaces and calculation tests together. Conflicting historical material remains archived and should not be reused as current copy.

## Independence and accountability

NEXON is an independent, community-initiated project built within the NEX ecosystem. NEX exchange status, licences or personnel do not approve or guarantee Staking Platform outcomes or future NEXON product governance. Responsibility must be named per operating entity and product.

{% hint style="warning" %}
**Roadmap boundary.** XO does not currently grant voting rights. Holding XO or EXON does not create an ownership interest, executive role, revenue claim or authority over another user's assets.
{% endhint %}
