# 安全与风险

> Agent 替你翻译，不替你决定要不要。

第二部分在「关在笼子里的 Agent」与「译者」之间划了一条线，并且说过：笼子回答的是安全问题，不是能力问题。这一节就是那个安全问题本身，按它自己的逻辑来讲。一个 Agent 要跨三个市场提出一条 Route（路径），在每一段腿执行时把整条路径攥在视野里，再把最后一段落在协议之外——它碰到的风险种类，比一个支付应用多得多；而每一种都必须作答，且不能把译者重新变回一只手。

Agent 的每一个动作都有边界、看得见、留记录。下面的每一条缓解措施，都是这三种性质中的某一种落在某一类具体威胁上；设计撞到工程绕不过去的极限时，极限会被如实写出来。

## 五类威胁 <a href="#five-classes-of-threat" id="five-classes-of-threat"></a>

{% tabs %}
{% tab title="Agent 权限" %}
**威胁。** 一个有资格行动的 Agent，可以做得比你的本意更多——更大的金额、一个你不会选的场所、一段你从未批准的腿。

**回应。** 权限是分层的，每一层都比外面那层更窄。最外层的上限是 Capacity（执行额度）——你押住的 XO 让你的 Agent 有资格执行的那部分——在任何 Route 被提出之前，先经 Bond Check（额度校验）核对。上限之内，每一条 Route 都以预览的形式呈现给你，逐段列出报价与有效期，只有你批准才会执行。Route 之内，每一段腿都在一份限定范围的委托（scoped delegation）之下运行，委托里写明资产、场所、金额与有效期。Route 执行期间，它所需的 Capacity 会作为 Capacity Reservation（额度冻结）被锁住，Route 关闭时释放。

撤销是链上的、即时的：通过撤销登记簿（revocation registry）收回的委托，会阻止下一段腿启动。至于让某一类 Route 无需逐条审批即可运行的 Pre-approved envelope（预授权范围），是 `Roadmap`（OP-18），不属于 v1 设计。
{% endtab %}

{% tab title="密钥" %}
**威胁。** 谁握着密钥，谁就握着资产。一个替你保管密钥的运行时，既是单点故障，也是整个网络上最值钱的攻击目标。

**回应。** 资产始终由你自己托管。Nexus Agent（连接体）从不持有你的根密钥；它持有的是委托——限定到某一段腿、到期自动失效、随时可撤销。因此，一个被攻破的运行时，最多只暴露当前委托给它的那几段腿，且最多只在剩余有效期之内。委托密钥丢失后的恢复，走一条带时间锁的路径，路径上没有任何一方能单独行动（`Design Target`）。根密钥的恢复是钱包的问题，不是协议的问题，本文不假装它是。
{% endtab %}

{% tab title="合约" %}
**威胁。** 协议自己的合约——Bond（押注）账本、Route 托管（escrow）、撤销登记簿——是代码，而代码有漏洞。

**回应。** 链上的暴露面被刻意压到最小。协议只持有它必须持有的东西：Bond 账本里已押注的 XO，以及 Route 存续期间托管中的 EXON。经由各段腿流动的资产，协议从头到尾都不经手。升级必须走[治理](../06-governance/README.md)一节里带时间锁的阶梯，所以任何改动抵达合约的速度，都不会快过 Seat（席位）持有者读到它的速度。审计是 `In development`；其范围是一项待定参数（OP-28）。本文不点名任何审计方，也不在结果出来之前宣称任何结论。
{% endtab %}

{% tab title="市场" %}
**威胁。** 报价在预览与执行之间变了。某段腿成交得比展示的差，或者根本没成交，这条 Route 就不再是你批准的那个意思了。

**回应。** 预览里的每一个报价都带有效期；报价过期的腿会重新询价，如果新报价突破了你的约束，Route 就退回给你。这些约束本身就是 Intent（意图）的一部分——`max_slippage`、`max_burn_rate`、一个截止时间。超出约束的成交就是一段失败的腿，而失败的腿会沿它来的路触发 Rollback（回滚）。一条 Route 的最终性，就是它最慢那段腿的最终性。针对过期、偏离或不可用数据的熔断器，会在某段腿基于坏数据运行之前先暂停 Route；触发阈值是 `Design Target`（OP-17）。
{% endtab %}

{% tab title="对手方与现实腿" %}
**威胁。** 最后一段腿落在协议之外。供应商收了款却不交付；预订确认了又被取消；卡额度发下来又被收回。

**回应。** 每一段 Real Leg（现实腿）都以一张 Landing Receipt（落地凭证）收尾——一份可验证的记录，写明 Leg Executor（腿执行方）确认了什么——并在 Route 最终关闭之前打开一个争议窗口。Leg Executor 的接入有三个条件：库存真实、确认可验证、其腿可退款。当更早的腿已经退回、而 Real Leg 却无法逆转时，Route 进入 `Partially unwound`（部分回滚）。剩下的缺口先从 EXON 托管里补，只有在托管耗尽之后，才动用这条 Route 在 Capacity Reservation 之下锁住的 XO；这一追偿的顺序与上限是 `Open`（OP-10）。
{% endtab %}
{% endtabs %}

第六类威胁——过期、偏离、不可用、被伪造或有争议的数据——贯穿上面每一段腿，在数据进入系统的地方处理，见[数据与预言机](../03-architecture/data-and-oracles.md)。

## 设计不回避什么 <a href="#what-the-design-does-not-hide" id="what-the-design-does-not-hide"></a>

{% hint style="danger" %}
**这套设计有三条边界，并且明说。**

**部分回滚可能需要人工处理。** 只要每一段腿都可逆，Rollback 就是自动的。可一旦 Real Leg 已经落地，仅靠代码并不总能恢复到先前的状态，一条 `Partially unwound` 的 Route 可能需要一个人——Leg Executor、Seat Council（席位议会）的成员、或者你——来了结剩下的部分。

**Real Leg 是最难的一段。** 供应商、发卡机构与持牌场所都在协议之外。协议核验它们出具的凭证，不控制它们的库存、它们的系统或它们的偿付能力。

**链无关，意味着继承每一条链的风险。** 每一段腿都在其资产原生的地方结算，所以一条 Route 暴露在它触及的每一条链、每一个场所的最终性、拥堵与合约风险之下。Translation Layer（翻译层）去掉的是对桥的需要，去不掉链本身。
{% endhint %}

## 三层约束，一句话 <a href="#three-layers-one-sentence" id="three-layers-one-sentence"></a>

上面所有内容，归结为一条 Route 从被提出的那一刻起就受到的三重约束。

① Agent 的执行上限由你 Bond 的 XO 决定（Capacity），超出额度的路径它根本发不起来；② 每一条 Route 在执行前是可见的、可拒绝的——你是审批者，不是旁观者；③ 执行中任何一段失败都会触发 Rollback，原路退回。一句话：Agent 替你翻译，不替你决定要不要。

{% hint style="info" %}
**本节口径。** 本节承诺：分层权限（Capacity、Route 审批、限定范围的委托、链上撤销）、自托管加委托密钥、任何一段腿失败即 Rollback、每一段 Real Leg 都有带争议窗口的 Landing Receipt。本节不承诺：任何具名审计方、时间锁路径之外的任何恢复机制、Real Leg 落地之后的自动化处理。待定项：[OP-10 · OP-17 · OP-18 · OP-28](../open-parameters/README.md)。
{% endhint %}
