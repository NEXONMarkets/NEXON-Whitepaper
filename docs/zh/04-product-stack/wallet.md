# 钱包 —— 金融主页与控制中心

*产品阶段 · Roadmap*

NEXON 钱包被设计成用户在生态里的**金融主页**：在一条路径抵达执行之前，理解自己的资产、仓位、权限、策略和待处理动作的地方。它不是一张余额清单，也不制造第二个收益来源。

## 状态统一，但不假装资产也统一 <a href="#unified-state-without-pretending-the-assets-are-unified" id="unified-state-without-pretending-the-assets-are-unified"></a>

一个统一视图要能说清价值**实际在哪**。XO 质押本金、待领收益、可赎回金额和外部资产，各有各的执行方、流动性和风险；EXON 现货余额与释放属于交易所侧的记录。

钱包指出负责的场所、网络、合约或托管人，而不是把所有条目都当成等价的现金。

对当前的 Staking Platform 机制，钱包应该显示：

| 显示项 | 说明 |
|---|---|
| 合格本金 `P` | 这笔订单的入金 |
| 28% 燃料 | 按当时 1 U 等值买入 EXON，存入燃料钱包 |
| 其余兑换 XO | 进入质押，每 12 小时结算 |
| 燃料钱包 | 只能在提取收益时销毁，不能转出、不能交易 |
| 选定期限与权重 | 30 / 90 / 180 / 360 / 540 天，1.00 – 1.50 |
| 12 小时 Epoch 计息与参数版本 | 每笔计息记下它当时用的规则版本 |
| 提前退出条件 | 仅 30 天期限适用 |
| 待领收益与赎回选择 | T+0 / 30D / 60D |
| 等值 EXON 销毁与净释放 | 选中带销毁的档位时显示 |

**一个显示不是一次可执行的报价。** 价格与提现条件要从负责的系统实时刷新。

## 权限中心 <a href="#permission-center" id="permission-center"></a>

钱包应该让 Agent 的权限一眼可读。用户可以查看：哪个应用可以读账户状态、可以动哪笔资产、最大金额是多少、有哪些目的地限制、什么时候过期、还剩多少未用的权限。

撤销停止的是**未来的使用**；它倒不回一次已完成的转账或市价单。这两件事在界面上必须是两句话。

持币不会扩大这些权限。XO 的「价值锚」与 EXON 的「流通引擎」是叙事定位，和账户授权是两回事。

## 决策支持 <a href="#decision-support" id="decision-support"></a>

钱包是用户从「发现」走到「决定」的那个点。它可以组织关注列表、风险提醒、情景比较、储备策略和路径历史。AI 可以做总结和解释，并且要标出不确定性、来源，以及**观察到的余额、估算价值与可执行报价之间的差别**。

生态还可能通过第三方协议接入去中心化预测市场体验。这些市场能表达对未来的看法，但不能保证未来发生什么。NEXON 提供基础设施与入口，不做这些市场的运营方、对手方或结算权威。

在这类入口开放之前，产品条款要写清楚：

* 独立协议与托管模型；
* 资格与禁止辖区；
* 市场创建者与结算来源；
* 费用、流动性与结算资产；
* 争议与无效市场的处理规则；
* 预言机与操纵风险；
* 一个预测价格既不是建议，也不是确定性。

参与需要一次单独的用户审批。**社交人气或 AI 预测不会自动开仓。**

## 质押入口，不是新经济 <a href="#staking-access-not-new-economics" id="staking-access-not-new-economics"></a>

钱包可以为已有的 Staking Platform 提供入口。这个入口复现已确认的机制和当前参数版本：它改不了 28% 的燃料拆分，改不了 20 代与 V1 – V12 的比例，也不会去暗示本金受保护。任何一次收益演算都写明它依赖的价格假设。

## 它在闭环里的位置 <a href="#its-place-in-the-loop" id="its-place-in-the-loop"></a>

社交 App 提供用户自己挑的语境；钱包持有金融状态与策略；PayFi 构造被批准的路径。执行之后，凭证回到钱包，用户在这里对账「到底变了什么」。商城或卡的交付作为**一个独立的履约状态**继续可见。

这让钱包成为发现与行动之间的一块控制面板，而不是一个自动交易员。
