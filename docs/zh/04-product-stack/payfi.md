# AI 原生 PayFi

*产品阶段 · 已上线 · 产品角色 · 价值路由器（Value Router）*

AI 原生 PayFi 是价值连接命题最清楚的一次产品表达。它从用户想要的结果出发，把它变成一个看得见的序列：

**意图 → 路径 → 策略校验 → 用户审批 → 执行 → 凭证。**

它可以协调受支持的金融与消费动作，同时每一个场所、托管人、发卡机构或供应商，仍然对自己那一段负责。

它之所以叫「AI 原生」，是因为**含义先于菜单**。它之所以叫 PayFi，是因为金融状态和支付/使用被放进同一段受控的旅程里考虑。

## 六步，逐步展开 <a href="#six-steps-unpacked" id="six-steps-unpacked"></a>

{% tabs %}
{% tab title="1 · 捕获目标" %}
用户说出结果、预算、截止时间、可用余额、受保护的储备、成本上限和审批偏好。自然语言的好处是可以一口气把这些说完。

应用把它们转成结构化意图，并把含糊的地方挑出来。碰到不支持或不合格的请求，它给出一个解释——**而不是一个看起来成功了的模拟结果**。
{% endtab %}

{% tab title="2 · 预览路径" %}
PayFi 提出一条或几条合格路径，**不移动任何价值**。预览把每一段拆开写清楚：

* 来源资产与目的地；
* 金额、报价、预估成本与有效期；
* 负责的场所、合约、发卡机构或供应商；
* 需要满足的身份与辖区要求；
* 需要授出的权限；
* 哪些步骤不可逆、哪些依赖退款；
* 预计拿到的结算与履约凭证；
* 价格、余额、库存或策略变化时的行为。

比较按用户的约束排序。任何可能影响排序或推荐的路由激励，都必须披露。
{% endtab %}

{% tab title="3 · 跑策略校验" %}
硬控制在模型判断之外：账户状态、身份引用、白名单、黑名单、消费限额、报价新鲜度、储备下限，以及产品自己的规则。**模型的高置信度推翻不了一条没通过的规则。**

涉及当前的 Staking Platform 订单时，PayFi 可以解释并校验 7228：72% 建立 XO 质押 / PV 基数，28% 买入 EXON 注入 Treasury Liquidity，另有等值 28% 的 EXON 在用户账户里被校验、校验完仍归用户。产品界面不改这些数值，也不把这次校验说成一笔费用。
{% endtab %}

{% tab title="4 · 请求有边界的权限" %}
审批写明动作、最大金额、资产、目的地、执行方、有效期，以及允许的后续分段。未用掉的权限在被消耗之前可以撤销。长期规则必须有自己的金额与时间上限，以及一个显眼的关闭开关。

**XO 与 EXON 余额不会给 PayFi 任何常驻权限。** 账户权限来自用户和责任执行系统。
{% endtab %}

{% tab title="5 · 协调执行" %}
PayFi 只把已批准的那条指令发给对应执行方，并在继续之前复检依赖关系。兑换可能在场所结算，链上转账在网络结算，商户订单需要供应商确认。

**应用呈现一条路径，但绝不把「已提交」标成「已完成」。** 报价过期就重新报价并再问一次；余额变了就重算，不偷偷换资产；前段结算、后段失败就停下、保住部分状态、进入已披露的退款、对冲或争议流程。
{% endtab %}

{% tab title="6 · 出具凭证" %}
一份路径凭证回答六个问题：**请求了什么、批准了什么、每一段谁执行、什么结算了、什么履约了、还有什么没结掉。** 原生标识与时间戳让整个账户可审计。

凭证也是闭环的反馈边：钱包可以用用户授权的历史改进未来的策略与提醒；用户可以选择把某些结果分享到社交。**金融与身份数据默认保持私密。**
{% endtab %}
{% endtabs %}

## 产品经济归产品自己 <a href="#product-economics-belong-to-the-product" id="product-economics-belong-to-the-product"></a>

定稿的 Tokenomics 定义的是 Staking Platform 的经济，不是未来每一条 PayFi 路径的经济。PayFi 的费用、点差、支付资产、发卡机构收费、商户成本与退款条款——如果有——都要在执行之前写在对应的产品条款里。

AI 也不生产质押收益。基础年化、期限权重、Epoch、提前退出处理、动态奖励与赎回销毁，都是 Staking Platform 应用的机制参数。**PayFi 的模拟必须复现这些参数，并写明它用了哪些假设。**

## 安全与问责 <a href="#safety-and-accountability" id="safety-and-accountability"></a>

这个产品至少需要：最小权限、模拟、报价有效期、确定性策略校验、撤销、交易限额、提供方白名单、异常检测、防重复执行、可审计凭证与事件升级路径。**提示词和隐藏的推理链替代不了这些控制。**

每一段的责任方都要保持可见：PayFi 协调；场所结算；托管人按自己的条款控制资产；发卡机构授权卡交易；商户或旅行供应商履约。**责任方指不出来的路径，就不该被摆出来当作可以走。**
