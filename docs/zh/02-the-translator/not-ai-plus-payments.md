# 这不是「AI + 支付」

> 这个行业眼下大部分精力都花在给 Agent 建笼子：限额、限时、白名单。全都必要——但它们回答的是安全问题，不是能力问题。关在笼子里的 Agent，仍然只是一只更小心的手。而当一个 Agent 能同时读懂三个市场，它就不再是手了。它是译者。

NEXON 和一个正在壮大的产品类别共享一套词汇——Agent、支付、结算、链上通道——除此之外几乎什么都不共享。这一节的存在，是为了让这个差异用本文自己的话说清楚一次，而不是留给读者去推断。

## 问错了的问题 <a href="#the-wrong-question" id="the-wrong-question"></a>

眼下几乎所有关于 Agent 与钱的讨论，都是关于限制的讨论。Agent 能花多少？花多久？跟谁花？密钥能不能撤销？这些问题值得回答，NEXON 也回答了——第三部分详细描述了 Capacity 上限、逐条 Route 审批、限定范围的委托与撤销，第六部分把它们当作安全面来处理。

但它们回答的是安全问题，不是能力问题。一个消费限额告诉你 Agent 能造成多大损失。它对 Agent 能*理解*什么，一个字都没说。一个被限额和白名单约束着的 Agent，拿到上一节那个东京的请求，仍然卡在和人一样的那堵墙前面：它能沿着一条通道搬钱，却完全不知道一笔仓位、一枚代币和一间酒店房间是同一份价值的三种表达。笼子改变不了笼子里的东西。

## 三个市场，两个方向 <a href="#three-markets-both-directions" id="three-markets-both-directions"></a>

这个类别里的大多数产品解决一个问题：已经在链上的钱怎么花出去。那是一条通道，单向运行，从数字世界到最后一公里。这是个真问题，把这条通道做得更快更便宜也是真工作。但它不是 NEXON 的工作。

NEXON 是为另一个问题造的：三个市场如何互相听懂。资本市场、数字资产、真实消费，三向、双工地连在一起——一笔仓位变成一张订单，一次消费变成一笔持有，一笔持有变成一笔仓位。单向通道表达不了其中任何一条，跑得再快也不行。译者可以，因为译者不在乎句子往哪个方向走。

{% columns %}
{% column width="50%" %}
**一只手**

- 执行它被交代的指令，在一条通道上。
- 读的是金额、地址和限额。
- 靠把它做小来变得更安全。
- 止步于价值离开链的那一点。
{% endcolumn %}

{% column %}
**一个译者**

- 兑现它被要求的结果，跨越三个市场。
- 把所有权、流动性和使用权当作同一种语言来读。
- 靠让它可问责来变得更安全——见第三部分。
- 止步于 Real Leg，不管那在哪个市场里。
{% endcolumn %}
{% endcolumns %}

## 意图往哪个方向流 <a href="#which-way-intent-runs" id="which-way-intent-runs"></a>

还有第二个更安静的差异，关乎一个 Intent 从哪里来。

有一种现成的看法认为支付是原语，社交行为从中长出来——人能互相付钱了，对话就会跟上。NEXON 的设计方向正好相反。意图诞生在对话里：你想去东京，是因为朋友发了照片；你想加仓，是因为群里在讨论。所以社交层不是挂在支付产品上的一个功能。它是源头。对话产生 Intent，Intent 产生 Route，Route 产生结算。社交 → 意图 → 执行，从不反过来。第四部分会描述它变成什么样的产品；这里要说的只是，这个箭头有方向，而 NEXON 的方向是定死的。

<details>

<summary>NEXON 同样在建什么，它们在本文的哪里</summary>

以上并不意味着 NEXON 对约束漫不经心。它意味着约束不是定位。

- **Capacity** —— Agent 可执行上限，由押住的东西决定：[信任与抵押](../03-architecture/trust-and-bonding.md)。
- **逐条 Route 审批与限定范围的委托** —— 每条 Route 在运行前可见、可拒绝；每一段的委托都限定了资产、场所、金额与有效期：[Agent 运行时](../03-architecture/agent-runtime.md)。
- **撤销与 Rollback** —— 即时收回授权，以及一段失败时定义好的退回路径：[结算与托管](../03-architecture/settlement-and-custody.md)。
- **完整的威胁模型**：[安全与风险](../07-security-and-risk/README.md)。

</details>

一句话说清差异：这个类别的其余部分在研究怎样让 Agent 拿着钱又不攥得太紧。NEXON 在研究怎样让 Agent 明白这笔钱是用来做什么的。

{% hint style="info" %}
**本节口径。** 本节承诺：NEXON 的 Agent 被定位为跨三个市场、双向工作的译者，意图源自社交层；安全约束存在，并在第三部分与第六部分具体说明。本节不承诺：与任何点名产品的比较，或对其他系统能力的任何超出上述类别描述的断言。待定项：无。
{% endhint %}
